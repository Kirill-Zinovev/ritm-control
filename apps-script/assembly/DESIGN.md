# Экран сборщиков

Основа — предоставленный владельцем работающий RITM Assembly Web App. Сохраняем белые строки товаров, мягкий светлый фон, темно-синий текст, зелёную порезку, синюю сборку, фиолетовую упаковку и раскрытие сотрудников внутри артикула. CSS и базовые примитивы находятся в Index.html; отдельный React-проект не создаётся.

## Layout

Согласованный рабочий экран от 16.10.2026: слева белая панель поставок шириной 224px, выделенная синей заливкой активная поставка. Нет меню ERP и сводных KPI. Справа название поставки, поиск, обновление и «Короба», затем плотные строки товаров высотой около 82px. До 760px поставки превращаются в горизонтальные кнопки, товары — в карточки. Таблицы сотрудников на телефоне перестраиваются внутри карточки, без горизонтального скролла. Для длинного списка показываем 60 строк и кнопку продолжения; поиск всегда охватывает весь загруженный состав.

## Components

Исправление плотности от 19.10.2026: до 1200px раскрытие артикула ставит сотрудников и короба друг под другом. Карточка сотрудника имеет две области — имя/время и показатели операций; пустая третья колонка не резервируется. Меню короба позиционируется в пределах экрана и не расширяет строки. Цвета, шрифты и навигация сохраняются.

Канонический владелец токенов — `:root` в Index.html (модель B): primary → --primary, text → --ink, muted → --muted, background → --canvas, surface → --paper, border → --line; операции → --cut/--assembly/--packing. DESIGN.md отражает их значения. Шрифт Segoe UI обеспечивает кириллицу без сетевой загрузки. Числа табличные. Мягкая тень выделяет только окно/панель; таблица остаётся спокойной белой поверхностью с тонкими границами. Серые подписи и текстовое состояние дополняют цвет.

Операционные полосы зелёные/голубые/фиолетовые. Неизвестный факт отображается «—», неизвестный маршрут не превращается в нулевой факт. Коэффициенты в раскрытии подписаны отдельно по операциям, не суммируются в один KPI. Сотрудник — одна строка; поля ввода вынесены в единственное модальное окно. Формы и обратная связь используют существующие примитивы Index.html, без подключения отдельного React-приложения.

## Workflow

При смене поставки сбрасываются поиск и раскрытие строк; переключение блокируется во время записи или неизвестного результата. Поздние ответы предыдущего запроса не меняют выбранную поставку. Нативные select в форме намеренно оставляют раскрытый список и клавиатурное поведение ОС. Выбор имени запоминается только локально и не является авторизацией. Ошибка сохранения не очищает поля. Неопределённый результат сначала проверяется по прежнему ключу; повтор не создаёт новый ключ и не может менять замороженный состав операции. Обновляется только затронутый артикул.

Короба открываются модальной правой панелью. Панель читает реальные номера и заполненность из `Cartons`/`CartonContents`; новый короб создаётся отдельно от размещения. Размещение требует выбрать товар, короб и количество, показывает проверку остатка и подтверждается одной кнопкой. Сервер повторно проверяет вместимость, план и принадлежность короба выбранной поставке, применяет ключ повтора и обновляет локальную строку после подтверждённого ответа. «История» показывает только последнюю известную активность сотрудников из текущего среза, явно сообщает об отсутствии полного журнала в API.

Журнал работы, кнопки, диалоги и обратная связь переиспользуют существующие примитивы app. На телефоне выбор поставки занимает всю строку, статьи остаются мобильными карточками. При ошибке фонового чтения сохраняем прежние строки и показываем ошибку. Во время ввода фоновые обновления не стирают ввод. Тестовые поставки имеют явную метку; данные разных поставок никогда не суммируются на экране.
