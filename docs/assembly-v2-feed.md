# Separate Assembly v2 feed

Live readiness follow-up, 14 November: `POST /api/assembly-v2/refresh` is separate from the cache-only GET feed. Assembly calls it only after `assembly_v2_source_stale`, with an empty JSON object and the existing v2 POST signature (method/path/time/nonce/body hash). Nonces are replay-protected; source and printing refresh leases prevent concurrent reads. It refreshes the existing printing cache and its new-v2 snapshot job, without maintenance, notifications, Google writes or old queue delivery. A busy/failed refresh retains the previous snapshot and target data. A fresh cache skips the read. The target retries the GET feed once after an acknowledged refresh; no browser-open dependency or freshness timestamp fabrication is needed.

Canonical-lock correction (13 November 2026): use the existing `shipmentLock(scope, canonicalShipmentId)` helper, exactly as the old Assembly control endpoint. Historical locks of a physical department sheet cannot override the explicit unlock of the shared supply. Live read-only control receipts confirmed Kazan shop 2 and Ekaterinburg shop 2 were already unlocked on 5 November; their earlier v2 closed badges were an adapter error. No source lock is changed by this fix. The feed revision includes newer canonical lock checkpoint timestamps, so a lock/unlock can apply without inventing a printing composition change. The printing snapshot itself must still pass its independent freshness/identity checks.

The owner requested connecting RITM supplies to the new web Assembly on 13 November 2026 while employees keep using the old Assembly. This adds only `GET /api/assembly-v2/feed` and an import/route in `worker/cloud/runtime.js`. No old Apps Script, queue, delivery URL, acknowledgement, signing secret, printing source, notification or production operation is changed.

The RITM Site remains under its existing access policy. The new endpoint requires its own server-only `RITM_ASSEMBLY_V2_FEED_SECRET` (64 hex characters). Requests carry a two-minute timestamp, UUID nonce and HMAC-SHA256 of `[1,"GET",pathIncludingQuery,timestamp,nonce]`. The key grants access to this read-only feed only. It is never accepted by any old control/write route and never returned to browser clients. Runtime values belong in Sites secrets, not source or logs.

The handler reads existing `CloudStore.snapshot("printing")`, `scope()` and lease status. It never calls source refresh, maintenance, export, service constructors, Google readers/writers, outbox delivery or notifications. It requires a confirmed migration, intact snapshot younger than five minutes, matching production-move revision, no unconfirmed source mutation, and confirmed source sheet identity. Managed supplies use their shared `RITM-SUPPLY-UUID`; legacy sources retain `RITM-ROLL/BOX-sheetId`. Box positions retain their `box:sheetId` prefix, even when the raw UID matches another department. Source quantities are plans in pieces; physical print/cut/packing facts are not copied.

The response includes a complete active-ID roster, separately validated compositions and held-source issues. A missing part, bad quantity or duplicate position holds the entire shared supply; an unavailable source never becomes an authoritative empty roster. Deleted managed registry entries are not resurrected from old snapshot rows. Unlinked box sheets require an existing confirmed explicit transfer receipt. Materialized legacy box links remain supported. Source locks, including pending unlocks, block new work in the target. Manual Assembly-only additions retain their original manual position IDs. Market and source store confidence are explicit. There is no exact warehouse ID in the input; the receiving app preserves the original direction name rather than guessing a warehouse.

New Assembly pulls on open and every 30 seconds while visible, through a shared target-side lease/due check, so twelve collectors do not cause twelve source reads. The old Assembly continues its independent original delivery. Closing the new web page does not replace the old queue with a new unattended scheduler. Missing or stale input preserves target history and is shown in its connection screen.

Verification: ten pure source/auth tests, existing Sites/printing/assembly regression suites (70 total), and an actual compiled Workers + D1 test. The runtime test confirms authenticated feed access, unchanged anonymous protection of old APIs, and zero outbound Google calls, outbox rows or production operations. All mutation scenarios use isolated fixtures. Actual publication and source-read results are reported separately.
# Parallel production delivery, 14 November 2026

Confirmed production/roll operations now atomically enqueue `assembly_v2_supply_deliveries` in CloudStore checkpoints. A separate lease, retries and explicit target receipts keep this independent of `cloud_sync_events`. The existing legacy delivery algorithms, keys, URLs and receipts are unchanged. Canonical lock changes and confirmed explicit transfers enqueue their own v2 delivery. A fresh source snapshot can recover the complete roster.

Runtime secrets `RITM_ASSEMBLY_V2_TARGET_URL` and `RITM_ASSEMBLY_V2_TARGET_TOKEN` address only the existing private Assembly v2 Site. The provider-issued service token stays in runtime secrets; the Site audience is unchanged. Redirects never receive the token. Receipt validation requires source revision, canonical shipment IDs and persisted positions. Existing maintenance and authorized RITM requests retry pending jobs; no process-owned timer is assumed.

`POST /api/assembly-v2/events` receives native v2 work/cancellation events with the separate v2 HMAC key. Its signature includes method, path, time, nonce and body hash. D1 stores immutable event identities before returning acknowledged IDs. Replays do not duplicate work; a changed committed event is rejected. Legacy import events are not replayed into RITM. Existing cached legacy facts are overlaid with v2 work and cancellations for both `/api/printing` progress and `/api/assembly` employee reports. Unknown saved coefficients remain unknown. Private raw stage evidence is removed from public printing responses.
