# Производственный контроль зарегистрированных листов

Реестр `agent/productionRegistry.js`: четыре производственных документа и десять уникальных пар documentId/gid. Рулонная печать добавлена только для чтения на вкладках заказа, журнала и дневной сводки; сводка не считается повторно в KPI, а формула плановой площади ждёт утверждения. Новая таблица отсутствует в белом списке записи. Рабочая защищённая конфигурация использует копию реестра вне Git. Существующая SQLite сохраняется. Производственный Google Reader остаётся только для чтения.

## Границы инцидентов

`IncidentStore.setMonitoringScope` переводит открытые проблемы исключённых листов в `out_of_scope`. Они не считаются исправленными, не отправляют новые уведомления, недоступны для заявки на исправление и остаются доступны фильтром. `reconcile` проверяет область и для старых CSV-адаптеров: зависимость «История производства» читается для KPI, но не создаёт инциденты ячеек вне whitelist. Ошибки подключения документов и технического API сохраняются отдельно от ячеек.

Worker assembly/printing и полные зависимости KPI не изменены. Журнал продолжает включать выпуск других поставок, даже если их листы не входят в область новых инцидентов. Это не повторное сложение сводки с историей.

## Чтение

Метаданные не запрашивают гигантский список merges, который для первого магазина превышал лимит ответа. `doctorRead.js` последовательно читает большие листы порциями по 200 строк, не более 100000 ячеек в одном запросе; максимум зарегистрированной области 500000 ячеек. Пауза Google Reader 2000 мс остаётся. OFFSET/Cash/Нормы/старые вкладки — зависимости; их данные не заменяются и не исправляются. Частоты Google вызовов не повышаются ради параллельной нагрузки.

## Проверки перед утверждением

`businessDoctor.js` выполняет только предварительные проверки новых бизнес-правил. Наблюдения отдельно от активных инцидентов. Измерения и примеры показаны в карточке каждого листа. Новые бизнес-правила не имеют режима approved в этой версии, подтверждение записи Sheets не добавлено.

| Лист | Предложение | Обязательные ограничения |
|---|---|---|
| Все коэффициенты | Сумма B/C/D → E; сверка текущего дня | IMPORTRANGE внешних документов не проверены изнутри; нулевой коэффициент не доказывает отсутствие работы |
| По дням · Дашборд | Командный средний, динамика завершённых дней | Исключить сегодняшнюю незавершённую смену; согласовать календарь и состав команды |
| OZON НОВЫЙ ГОД | План площади, сопоставление плана/журнала/остатка | План J не заменяет факт L; старый выпуск может отсутствовать в журнале; статусы и ручные корректировки требуют исключений |
| Журнал выпуска | Уникальность ID записи и связность | Частичные записи заказа/рулона допустимы; J/L — значения, формулы не обязательны |
| Выпуск по дням | QUERY sum(L) по дате/сотруднику/операции; динамика | Печать/резка разделены; QUERY не удаляет дубли; динамика KPI берётся из verified snapshot существующего Worker |

| Товары НОВАЯ ПЕЧАТЬ 20.07.2026 | K=sum(G:J), неоднозначность артикула, контекст поиска | Cash/другие вкладки и допустимые ручные значения нужно учитывать; #N/A не доказывает повреждение формулы |

## Windows

Основное задание `RITM Intelligence` остаётся без изменения триггеров и запускает фоновый агент. `schedule.js` задаёт интервалы 600 секунд от начала проверки; длинная проверка пропускает занятые окна без перекрытия.

Отдельное задание `RITM AI Center` — только вход пользователя Windows, без повторяющегося триггера. Устанавливается `Install-AICenterTask.ps1`, вызывает `Open-AICenter.ps1`, ждёт localhost:4318, ищет Яндекс в App Paths/StartMenuInternet и проверяет файл/ProductName. Окно разворачивается через штатный Win32; профиль AI Center хранится в защищённой пользовательской папке. Браузер по умолчанию не меняется. Отказ браузера не останавливает агент. DebugPort применяется только вручную при визуальной проверке, не указан в задании Windows.

Автозапуск после нового входа не равен доказательству перезагрузки: без повторного входа проверяется запуск задания вручную, конфигурация триггера и фактический процесс. Не утверждать, что ПК перезагружался, если этого не было.
