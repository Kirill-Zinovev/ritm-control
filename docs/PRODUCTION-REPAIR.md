# Исправление производственных формул по запросу

Решением владельца от 10.10.2026 обязательный отдельный живой тест G247 отменён. Подтверждение эталонов включает контроль, но не разрешает запись. Исправление каждой ячейки подтверждается отдельно.

## Что реализовано

- Используется существующий движок TestRepairService: неизменяемое предложение, срок 10 минут, подтверждение, резервная копия, журнал, повторное чтение, диагностика и отдельный откат.
- ProductionRepairService допускает только четыре вида подтверждённых нарушений Formula Intelligence: число, текст, удаление или другая формула вместо утверждённой.
- Адрес извлекается сервером из инцидента и SQLite, а не из клиентского запроса. Проверяется действующий эталон, его версия, поколение инцидента и белый список трёх документов/семи листов.
- Отдельный аккаунт записи. GoogleSheetsReader сохраняет scope spreadsheets.readonly. Ключи вне репозитория, только локальные закрытые endpoints /api/intelligence/formula-repair.
- Перед записью проверяются нативное содержимое, объединение, ограничения ввода, отображаемый/вычисленный результат и версия эталона. Объединённые области допускаются только через неизменившуюся защищённую верхнюю левую ячейку. Ячейки с проверкой данных пока блокируются.
- SQLite хранит предложение, подтверждение и исходное значение до вызова Google. Используются уже существующие таблицы test_repair_proposals/test_repair_events; название историческое, записи находятся в базе основного агента, тестовая база 4319 не затрагивается.
- В Google отправляется одна операция updateCells с диапазоном одной ячейки и маской userEnteredValue. Форматирование, нормы и права сотрудников не изменяются.
- После записи сравниваются точная формула и объединение, проверяется отсутствие ошибки вычисления и наличие результата. Точное числовое значение не угадывается: если нет утверждённого бизнес-правила, показывается фактический результат без заявления о правильности всей бизнес-логики.
- Свежая успешная проверка Table Doctor должна закрыть именно этот инцидент. Другие инциденты документа не мешают подтверждению этой ячейки.
- Повтор успешного запроса возвращает сохранённый результат без второй записи. Сбой/таймаут после начала записи оставляет uncertain и запрещает автоматическое повторение. Перезапуск не повторяет незавершённые операции.
- Откат формируется из сохранённого исходного native value, предлагается отдельно и отменяется при изменении ячейки или эталона.

## Включение владельцем в Windows

Команда использует существующие защищённые каталоги RITM, проверяет отдельный ключ и права Google, сохраняет конфигурацию и вызывает существующий Restart-Agent.ps1. Рабочие Google Sheets не изменяет.

```powershell
& 'C:\workspace\ritm-fbo-redesign\scripts\windows\Enable-FormulaRepair.ps1'
```

По умолчанию ищется уже подключённый защищённый ключ ritm-test-writer. Этот аккаунт после явного включения используется основным агентом для согласованных производственных операций; его имя не доказывает изоляцию в Google. Если ключ не найден, повторить команду с `-KeyFile 'локальный-путь-к-отдельному-ключу.json'`. Ключ не передавать в чат. Ключ чтения отвергается. Если Drive API включён, скрипт проверяет `capabilities.canEdit`. Если Drive API выключен, он использует уже включённый Sheets API для проверки доступа к конкретному документу и листу, но явно помечает право записи как непроверенное. Google отклонит точечную запись, если права окажутся недостаточными; это случится только после явного подтверждения владельцем и не будет автоматически повторено. Скрипт не меняет разрешения документов.

Переменные закрытой конфигурации:

| Параметр                                | Значение                                                  |
| --------------------------------------- | --------------------------------------------------------- |
| RITM_PRODUCTION_REPAIR_ENABLED          | true только после подключения владельцем                  |
| RITM_PRODUCTION_WRITER_CREDENTIALS_FILE | отдельный защищённый файл вне Git                         |
| RITM_PRODUCTION_WRITER_EMAIL            | проверенный отдельный сервисный аккаунт ritm-intelligence |

Основной порт остаётся 4318, интервал 600 секунд, существующая SQLite/автозагрузка сохраняются. Для отключения: установить RITM_PRODUCTION_REPAIR_ENABLED=false в защищённом config.json и перезапустить основной агент. Отключение не удаляет историю/ключи.

Существующий HTTPS-адрес Tailscale в RITM_PUBLIC_ORIGIN сохраняется. Это совместимость с удалённым просмотром, а не разрешение удалённого исправления. Все endpoints исправления требуют localhost/127.0.0.1, локальное соединение, сессию владельца и точный локальный Origin; запросы с удалённым Host/Origin или заголовками прокси отклоняются. Само имя .ts.net не доказывает приватность сети: наличие Tailscale Funnel необходимо проверять отдельно. Скрипт не меняет настройки Tailscale и не открывает API в интернет.

## Использование

1. Утвердить проверенные формульные области в «Настроить защиту формул».
2. Выполнить проверку. Для подтверждённой подмены открыть карточку.
3. «Предложить исправление» читает ячейку и сохраняет точный план без записи.
4. Проверить документ, лист, адрес, исходное значение и формулу. Подтвердить согласование отсутствия параллельного редактирования и нажать кнопку с точным изменением. Набирать формулу заново не требуется.
5. Нажать подтверждение. Проверить фактический результат и журнал.

## Ограничения

Google Sheets не предоставляет атомарный typed compare-and-set для такого исправления. Между чтением и записью другой редактор может изменить ячейку/зависимости; повторное чтение уменьшает риск, но не исключает его. Не блокируем сотрудников и не меняем права. Исправлять в согласованное окно без редактирования этой области.

Программный белый список не изолирует аккаунт на стороне Google. «Редактор для всех по ссылке» может дать ему права вне ожидаемого перечня. OAuth spreadsheets — широкий scope; приватный ключ и локальный процесс необходимо защищать.

При uncertain нужна ручная сверка журнала и ячейки: приложение не сбрасывает состояние и не повторяет запись автоматически. Контекстные #N/A/пустые строки не являются самостоятельным основанием для восстановления. Эталон берётся только из утверждённой SQLite-версии.

Проверки программного механизма используют изолированные локальные ответы. Это не доказательство выполненной записи в производственный Google-документ. Настройка и первое реальное конкретное изменение требуют участия владельца.
