# Сборка по направлениям: компактный интерфейс

Существующие исходные задания и идентификаторы позиций остаются раздельными. Группировка маркетплейс / город / магазин меняет только представление. Нераспознанные направления не объединяются по догадке, неподтверждённые магазины остаются в общем списке. Одинаковые артикулы разных заданий сохраняют исходные позиции и журнал.

## Assembly

- По умолчанию — незавершённые товары. Готовые и все позиции доступны отдельными вкладками.
- У каждой строки есть действие записи работы. Под строкой — история, этикетка, добавление в короб; сотрудники и записи раскрываются только по запросу.
- Панель коробов показывает текущую позицию, фактическую упаковку, распределённое количество и доступный остаток. Количество и подтверждение закреплены внизу.
- Выбор коробов сохраняет магазин, вместимость, закрытие, отмены и распределение излишков на склад. Начатая запись удерживает исходные идентификаторы задания и позиции.

## Главный RITM

В «Поставках» основное представление — направления. Внутри направления доступны магазины, все исходные задания, поиск, фильтры готовности, статус закрытия для сборки и переход к прежнему управлению заданием. Тяжёлые таблицы состава монтируются только при переходе в управление.

Три показателя сборки читаются из одного снимка WorkLog: `cut`, `assembly`, `packing`. Каждый этап использует существующее сопоставление исходной позиции, алиасы старых UID, проверки дублей и журнал отмен. Производственная порезка печатников не подставляется вместо резки сборщиков. Неполные данные не становятся нулём или полной готовностью. Полосы ограничены планом по каждой позиции; фактическая выработка в журналах не меняется.

## Перенос между участками

Живой отказ Google по JA0037.A0470: `Invalid requests[1].copyPaste: This operation is not supported on a range with a filtered out row.`

Добавление строки теперь формирует относительные формулы через `updateCells`, без `copyPaste` и без снятия фильтра. Новые планы хранят исходные формулы; старые сохранённые планы читают свою строку шаблона до атомарного запроса. Перед записью переноса повторно проверяются отсутствие назначения и неизменность старого состава. Неподтверждённая запись не повторяется без сверки; исходная позиция сохраняется до подтверждения назначения.

## Проверка

Проверяются группы городов / магазинов / маркетплейсов, неизвестные направления, частичные данные, отменённые записи, раздельные этапы, фильтрованная строка шаблона, старый план переноса, сохранение прежних строк и фильтров. Браузерная проверка записи работы и размещения выполняется только в локальной тестовой среде. Реальный перенос проверяется отдельно по исходному ID операции.
