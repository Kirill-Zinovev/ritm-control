# Effective throughput for the production forecast

The resource preference `rateMode: auto | manual` is optional; absent means manual for backwards compatibility. Auto configuration stores rate 0 plus the owner-selected unit/work calendar. It does not persist a guessed speed. Effective rates are derived in memory from each fresh printing snapshot; no production cells, quantities, coefficients, output records, notifications or historical dates are written.

The estimate is the median of positive output per completed active working day in the preceding 28 Moscow calendar days, divided by the configured shift duration. Require at least 3 valid active days. Today is excluded because it is incomplete. Days without work do not describe productive capacity; non-working dates are excluded. This is effective shift throughput including usual pauses, not a measured machine cycle rate. A delayed bulk completion entry can distort a day; median reduces a single spike but cannot reconstruct actual elapsed work. Work calendars still require owner input.

Use only validated active journal events: roll printing/cutting, box printing/cutting and both stock journals. Plans, completed-roll registries, daily summary sheets and seasonal output are never added as another fact. Existing upstream cancellation filtering remains authoritative. Source-qualified event IDs count once; conflicting duplicate facts invalidate affected samples. Incomplete units invalidate a full day's sample for that unit rather than undercounting it. Xerox sheets use saved physical sheets, not rounded product quantities. Other resources permit pieces or square metres. Cut resources aggregate their own department, separately from printing.

Printing events carry the uniquely resolved source-order machine. Unlinked historical facts retain their original KPI but do not acquire a machine from today's article/catalog; unknown/cross-department machines cannot train a printer. Thus some old output remains unsuitable for per-machine estimates. Old cached snapshots without machine metadata must refresh before supplying printer samples.

Stale/unavailable journals, missing stock journals, source quality errors (roll source), insufficient samples or missing work windows do not get a fallback speed. Auto mode can be saved while waiting for enough observations, with an explicit reason in the settings and unknown ETA. Owners can switch to manual, optionally copy the displayed estimate and correct it. Manual values take priority, remain unchanged by journal updates and preserve ordinary revision-conflict/origin/role checks. Managers can still edit deadlines, not capacities.

The same resolved planning object feeds list estimates and calendar lanes. The raw resource preferences remain separate for editing/export. Shared queue competition, print/cut overlap and partial Xerox conversion remain unchanged.

If an earlier position has a disputed production mark, later valid work on the same configured printer and its downstream cutter may be displayed as provisional. Its final production and packing deadlines remain unknown until the disputed work is resolved; a missing or unconfirmed speed never produces a provisional interval.

Catalog machine groups in the workload screen are only a display: a forecast task remains in its actual roll or box source department. If the catalog points to another department, the source sheet's explicit machine is used only when it belongs to the source department; otherwise its machine stays unconfirmed. Dedicated box-stock sheets carry their source UID in column AD even when the header is blank; conflicting stock layouts are rejected rather than matched by article alone.

Packing uses a separate owner-configured Assembly shift and a rate in pieces/hour. Automatic mode applies the same 28-day, three-completed-day median to active, source-qualified Assembly WorkLog packing events; duplicate event IDs are not counted twice and conflicting IDs invalidate affected days. Manual rates retain precedence. A stale or incomplete Assembly journal never supplies a guessed rate.

Packing is scheduled in a single shared queue after each confirmed cut batch, with existing cut stock eligible immediately. The queue includes active warehouse-stock positions by their exact Assembly identity, including archived source positions, and confirmed Assembly-only additions. An unknown source, conflicting identity, stale stock list, missing fact or unconfirmed upstream queue blocks unfinished packing forecasts rather than dropping work. Assembly-only additions never contribute to print/cut plans. Packing and shipping deadlines remain separate; only confirmed packing output is shown as fact. Source sheets, journals and carton records remain read-only.

Stock-source confirmations are bounded by the actual packed quantity, including any over-plan packing. The audit retains the confirmed full quantity, while forecast calculations cap its contribution at the production plan. Confirmations validate the same combined legacy and Assembly v2 events shown by the forecast, including cancellations; a snapshot without the evidence needed to apply v2 events is rejected until refreshed.

When the owner confirms that an entire printed position was cut but the production mark is missing, planning stores an append-only, position-scoped confirmation with the original plan, owner and confirmation time. It is used only while the exact task, plan and printed quantity still match; an updated production mark supersedes it. It never writes the source sheets, journal, employee output, assumed performer or execution date. The process and calendar explicitly label owner-confirmed cutting.

For a Xerox position whose current sheet conversion differs from an older one, a current completion checkbox plus active journal entries for exactly one source document, sheet, SKU and journal position can establish the complete plan when their recorded product quantities sum to that plan. Missing, duplicate, conflicting or partial entries retain the ordinary source-cell interpretation.

Regression coverage lives in `tests/production-rate-estimate.test.ts`, `tests/production-planning.test.mjs`, `tests/printing.test.mjs`, `tests/box-printing-journal.test.mjs`, `tests/cloud-worker.test.mjs` and the existing domain runner.
