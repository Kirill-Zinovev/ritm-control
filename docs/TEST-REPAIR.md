# Подтверждаемое исправление тестовой G247

Этот модуль развивает существующий Table Doctor. Он выключен по умолчанию.
Производственные Google Sheets, Worker API и расчёты KPI не меняются.

## Ограничения доступа

- Только localhost:4319. Основной агент на 4318 остаётся только читающим.
- Единственный документ: идентификатор таблицы хранится локально.
- Только gid 231140854, лист «Проверка формулы», G247.
- Только два заранее заданных изменения: число 150 → =C247/D247 и отдельно подтверждаемый откат.
- A247 = TEST-ONLY-247; C247 = 124; D247 = 100.
- Отдельный аккаунт ritm-test-writer@ritm-intelligence.iam.gserviceaccount.com.
- Исходный GoogleSheetsReader и spreadsheets.readonly не расширяются.
- Новый RITM_TEST_WRITER_CREDENTIALS_FILE указывает на защищённый JSON вне Git.
- Конфигурация требует единственный включённый тестовый документ, утверждённое точное правило,
  выключенные производственные источники, Telegram и fixture demo, отсутствие PUBLIC_ORIGIN.
- API требует настоящий сеанс владельца, локальный Host/Origin и loopback-соединение.
  Bearer-only запросы и проксированные запросы отклоняются.
- Перед записью Google Drive API должен подтвердить capabilities.canEdit=true для теста
  и false (или недоступный документ 404) для обоих известных производственных документов.
  Чтение по ссылке не блокируется: оно необходимо существующему CSV-источнику RITM.
  Новый ключ проверяет только метаданные прав, производственные ячейки им не читаются.
  Не отправляется ни одного пробного производственного write-запроса.
  Для аудита нужен включённый Google Drive API; JWT содержит Sheets и drive.metadata.readonly.
- Этот барьер не является аудитом всех неизвестных документов Google Drive; отдельно
  утверждённый синтетический документ и жёсткий программный адрес остаются обязательными.

## Маршруты

Все маршруты находятся внутри существующего защищённого локального агента.

| Маршрут | Назначение |
| --- | --- |
| GET /api/intelligence/test-repair?incidentId=… | Предложения, состояние изоляции, измерения и журнал |
| POST /api/intelligence/test-repair/propose | Сохранить план; Google Sheet не изменяется |
| POST /api/intelligence/test-repair/{id}/confirm | Подтвердить конкретную версию и точный текст изменения |

Параметры documentId, sheetId, cell, формула и произвольные Google requests из клиента не принимаются.
Направление repair/rollback выбирает одно из двух жёстко заданных изменений.

## Жизненный цикл

1. Авторизованный владелец нажимает «Предложить исправление».
2. Сервис проверяет права отдельного аккаунта и читает реальную A247:G247 старым read-only клиентом.
3. В SQLite сохраняются неизменяемое предложение, UUID, SHA-256 версия, поколение инцидента,
   версия правила, исходные значения и срок 10 минут.
4. Даже при провале изоляции можно показать read-only предложение. Подтверждение и запись заблокированы.
5. Владелец вводит точный текст подтверждения и отмечает отсутствие параллельного редактирования.
6. Сервер повторно проверяет права, поколение/срок/правило и читает ячейку с зависимостями.
   Изменения, валидация данных, объединённая ячейка или несоответствие типов отменяют действие.
7. SQLite-транзакция единожды переводит предложение pending → executing и сохраняет
   подтверждение и резервное содержимое ДО записи.
8. Единственный Google batchUpdate содержит findReplace только для G247:
   полное совпадение «150», без regex, без поиска внутри формул.
9. Требуется ровно одна замена. После записи старый read-only клиент обязан прочитать
   именно formulaValue =C247/D247 и numberValue 1.24 при неизменных исходных данных.
10. Свежая успешная проверка Table Doctor закрывает инцидент. Затем предложение становится verified.
11. Повтор подтверждения verified возвращает прежний результат без Google write.
    executing/uncertain не выполняются повторно, даже после перезапуска.
12. Откат — новое предложение, требующее собственного подтверждения. Он допустим только
    для проверенного исправления и ожидаемой текущей формулы.

## Постоянное хранение

Только включённый тестовый модуль добавляет в отдельную тестовую SQLite таблицы
test_repair_proposals и test_repair_events. История существующего агента также получает
события предложения, подтверждения, резервного содержимого, записи, проверки и отмены.
Секреты и токены в SQLite не сохраняются.

## Параллельное редактирование и ошибки

Google Sheets не предоставляет этому API атомарное сравнение типизированной ячейки
и всех зависимостей вместе с записью. findReplace — дополнительное условие на сервере,
а не полная compare-and-swap операция. Оно не блокирует:

- замену числа текстом с тем же отображением;
- изменение C247/D247 между чтением и записью;
- изменение ячейки после записи;
- изменение и возврат прежнего значения между проверками.

Поэтому пользователь явно подтверждает отсутствие параллельного редактирования
на время испытания; постпроверка обязательна. Нельзя заявлять полное устранение гонок.

Запись не повторяется автоматически при HTTP/сетевой ошибке. Неизвестный результат
или неуспешная постпроверка переводят предложение в uncertain и запрещают новые записи.
При перезапуске executing → uncertain. Автоматического отката поверх возможных чужих
изменений нет. Для uncertain необходим отдельный будущий процесс ручной сверки;
автоматическое разрешение этого состояния в этой версии не реализовано.

Парсинг замены в формулу и обратной замены в число должен быть подтверждён реальным
сквозным тестом. Если Google возвращает другой тип или результат, сервис фиксирует
uncertain; он не выполняет незапрошенный fallback updateCells.

## Выявленное препятствие 09.10.2026

В обоих производственных документах метаданные разрешений показали anyone / writer.
С отдельным тестовым аккаунтом spreadsheets scope GET обоих документов возвратил 200.
Аудит разрешений выявил потенциальный доступ на запись. Реальный запрос Drive API вернул 403 accessNotConfigured / SERVICE_DISABLED: Google Drive API пока не включён. Обе причины блокируют дальнейшую запись. Разрешения рабочих документов
не изменялись. Попытка минимального drive.file scope не открыла тестовый документ
(GET 404), поэтому она не включена как неподтверждённый обход.

Пока владелец не устранит избыточный публичный доступ, испытание заканчивается
на предложении; G247 остаётся числом 150. Успешное реальное восстановление не заявляется.

## Проверки

Новые tests/intelligence-repair.test.mjs используют только локальные ответы API.
Они проверяют подтверждение и версии, подмену адреса, конфликт до/во время записи,
изменённые зависимости, срок, новое поколение, повтор/параллельный запрос, неизвестный
результат, постусловие, неуспешную диагностику, отдельно подтверждённый откат,
сохранение после рестарта, изоляцию конфигурации, OAuth JWT и защищённые маршруты.

Внешние рабочие таблицы не используются для повреждения формул или пробных записей.
