# RITM Intelligence — запуск Windows

## Требования

- Node.js 24.12 или новее, npm.
- Доступ к текущим CSV-источникам Google Sheets и RITM API.
- Ключ владельца минимум 32 символа; храните его в менеджере паролей.
- Для уведомлений: Telegram bot token и числовой chat_id владельца. Это необязательная настройка.
- Для Table Doctor: отдельный сервисный аккаунт Google с доступом «Читатель». Инструкция: TABLE-DOCTOR.md. Без него CSV-мониторинг продолжает работать.

Проект: C:\workspace\ritm-fbo-redesign. Команды ниже выполняются из этой папки. Никаких производственных таблиц они не изменяют. Не запускайте два агента с одной базой.

## Установка и первый запуск

    npm ci
    npm run build
    powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\windows\Initialize-Agent.ps1
    powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\windows\Start-Agent.ps1

RemoteSigned применяется только к запускаемому процессу; системная политика не меняется. Если групповая политика блокирует запуск, обратитесь к администратору.

Initialize-Agent спрашивает ключ скрытым вводом и сохраняет его в Windows DPAPI, привязанным к текущему пользователю и компьютеру. Директория данных ограничивается текущим пользователем и SYSTEM. Секреты не пишутся в Git или frontend.

Открыть кабинет: http://127.0.0.1:4318/?page=intelligence. Введите тот же ключ владельца. Терминал можно закрыть после перехода на автозапуск. Для обычного запуска остановка — Ctrl+C.

## Автозапуск без открытого терминала

Сначала выполните инициализацию. Для предварительного просмотра регистрации:

    powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\windows\Install-AgentTask.ps1 -WhatIf

Для установки и запуска:

    powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\windows\Install-AgentTask.ps1
    Start-ScheduledTask -TaskName "RITM Intelligence"

Планировщик запускает агента при входе текущего пользователя Windows через скрытый WScript/PowerShell. Повторное выполнение одной задачи запрещено. При аварии предусмотрены три перезапуска с интервалом две минуты. Дополнительный повторяющийся триггер раз в пять минут восстанавливает остановившуюся задачу, включая чистый неожиданный выход; MultipleInstances=IgnoreNew оставляет уже работающий процесс без изменений. Это восстановление процесса, а не частота проверок Google: проверки идут через 600 секунд после окончания предыдущего цикла. После аварийного завершения аренда базы истекает через 90 секунд; монитор продолжит историю и снимки.

Это запуск при входе пользователя, а не служба до входа в Windows. При выключенном компьютере агент не работает. Если политика Windows отключает WScript, используйте разрешённую администратором задачу с PowerShell и WindowStyle Hidden; не обходите корпоративную политику.

Проверить и остановить:

    Get-ScheduledTask -TaskName "RITM Intelligence"
    Disable-ScheduledTask -TaskName "RITM Intelligence"
    Stop-ScheduledTask -TaskName "RITM Intelligence"

Для продолжения после изменения настройки:

    Enable-ScheduledTask -TaskName "RITM Intelligence"
    Start-ScheduledTask -TaskName "RITM Intelligence"

Disable-ScheduledTask отключает повторяющийся триггер на время обслуживания: один Stop-ScheduledTask не является постоянной остановкой. После принудительной остановки дождитесь истечения аренды. При штатном Ctrl+C агент освобождает её сразу. Скрипты не заменяют уже существующую задачу с таким именем.

## Конфигурация и логи

По умолчанию данные находятся в %LOCALAPPDATA%\RITMIntelligence:

| Файл                                            | Содержимое                                                |
| ----------------------------------------------- | --------------------------------------------------------- |
| config.json                                     | Несекретные настройки                                     |
| owner.secrets.xml                               | Зашифрованные DPAPI секреты                               |
| intelligence.sqlite и служебные WAL/SHM         | Инциденты, история, снимки, очередь и аренда              |
| agent.log, agent.log.previous                   | Журнал процесса, ротация примерно 5 МБ                    |
| launcher.log, launcher.log.previous             | Запуски, ошибки настройки и коды завершения; ротация 5 МБ |
| agent.stdout.log, agent.stderr.log, \*.previous | Вывод Node и ошибка текущего/предыдущего запуска          |

Не копируйте каталог в публичный репозиторий. Для резервного копирования штатно остановите агент и копируйте всю базу с её служебными файлами либо используйте SQLite backup. DPAPI-секреты нельзя переносить на другой компьютер как обычный парольный файл.

.env.example описывает параметры для альтернативного запуска через переменные окружения. Node сам не загружает .env.example. Для повседневного Windows-запуска используйте DPAPI-скрипты.

Основные параметры:

| Параметр                      | Назначение / значение по умолчанию          |
| ----------------------------- | ------------------------------------------- |
| RITM_BASE_URL                 | HTTPS адрес проверяемого RITM               |
| RITM_CHECK_INTERVAL_SECONDS   | 600, минимум 60                             |
| RITM_AGENT_PORT               | 4318, только localhost                      |
| RITM_DATA_DIR                 | Долгоживущий каталог данных                 |
| RITM_REQUEST_TIMEOUT_SECONDS  | 25 на запрос                                |
| RITM_REQUEST_RETRIES          | 2                                           |
| RITM_SNAPSHOT_MAX_AGE_SECONDS | 1200                                        |
| RITM_SOURCE_REGISTRY          | Путь к собственному JSON-реестру            |
| RITM_DEV_ORIGIN               | Разрешённый loopback origin для Vite        |
| RITM_OWNER_TOKEN              | Ключ в окружении процесса, не в config.json |
| RITM_TELEGRAM_ENABLED         | true после настройки токена и chat_id       |
| RITM_TELEGRAM_BOT_TOKEN       | Секрет в окружении процесса                 |
| RITM_TELEGRAM_OWNER_CHAT_ID   | Числовой chat_id владельца                  |
| RITM_GOOGLE_CREDENTIALS_FILE  | Путь к секретному JSON вне репозитория      |
| RITM_DOCTOR_REGISTRY          | Путь к JSON с правилами Table Doctor        |
| RITM_DOCTOR_DEMO_ENABLED      | false; true только для помеченной фикстуры  |
| RITM_AI_MODEL                 | Резерв будущей модели; AI пока выключен     |

Меняйте настройки после остановки процесса, затем перезапускайте. Нельзя разрешать origin публичного сайта в локальном кабинете.

## Telegram

При первой инициализации можно использовать:

    .\scripts\windows\Initialize-Agent.ps1 -EnableTelegram

Потребуются собственный бот и chat_id владельца; сначала начните диалог с ботом. Реальные сообщения отправляются только если эта настройка включена. Для уже настроенного агента используйте существующий скрипт в режиме обновления только Telegram:

    .\scripts\windows\Initialize-Agent.ps1 -ConfigureTelegram -DataDir "$env:LOCALAPPDATA\RITMIntelligence-Preview"

Токен вводится скрыто в локальном PowerShell, chat_id — числовой. DPAPI сохраняется; ключ владельца и Google-путь не меняются. Не вставляйте токен в чат, аргументы команд или config.json. После ввода нужен контролируемый перезапуск существующего задания; если требуется, владелец поручает его Codex. Создайте бота через @BotFather и отправьте ему /start до настройки.

В первом этапе доступны уведомления о критических и высоких инцидентах и кнопка исходной таблицы. Суточные сводки, входящие команды и подтверждение исправлений ещё не реализованы. Неопределённый результат отправки показывается uncertain, без автоматической повторной отправки.

## Реестр источников

Экспортировать штатный реестр без перезаписи существующего файла:

    node agent/export-registry.js "$env:LOCALAPPDATA\RITMIntelligence\sources.json"

Укажите этот путь в RITM_SOURCE_REGISTRY. Новые CSV-источники используют adapter csv и явную схему. Формульные правила пока документируются, но не исполняются. Настраивать freshness можно только с утверждённым календарём: активные дни, часы и допустимый возраст. До этого отсутствие новых записей само по себе не является инцидентом.

## Однократная проверка без кабинета

    $env:RITM_DATA_DIR = Join-Path $env:TEMP 'ritm-intelligence-check'
    $env:RITM_BASE_URL = 'https://ritm-erp.zinovevkirill234.chatgpt.site'
    npm run intelligence:check

Эта команда читает реальные источники, записывает результаты и завершает процесс. Ключ владельца не нужен, потому что HTTP-сервер не запускается. Не используйте временный каталог для постоянного мониторинга.

## Ограничения

На машине без настройки ключа кабинет не открывает данные. Автозапуск нужно установить после инициализации владельца. Локальное хранилище не находится в serverless Worker и не публикуется в Sites. Нужны отдельная авторизация и серверный транспорт для общего удалённого кабинета.

Не настроены AI API, авторизованный доступ к формулам, бизнес-календарь актуальности и автоматическая сверка FBO-дашборда. Статусы честно отражают это. Разрешения первого этапа — только чтение. Production-деплой не выполняется.

## Приватный доступ с других устройств

Используется уже установленный Tailscale. Serve проксирует только локальный http://127.0.0.1:4318 в HTTPS внутри tailnet; Funnel не включается, внешний порт API и правила роутера не открываются. Точный собственный HTTPS-origin внесён в RITM_PUBLIC_ORIGIN защищённого config.json; Start-Agent допускает этот параметр. Google/Telegram-секреты к прокси не относятся.

    tailscale serve --bg --https=443 http://127.0.0.1:4318
    tailscale serve status

Для телефона/другого компьютера: установить Tailscale, войти в ту же приватную сеть и открыть HTTPS-адрес ПК, показанный serve status, с ?page=intelligence. Затем войти ключом владельца RITM. Доступ других членов tailnet определяется её существующими ACL и дополнительно авторизацией RITM. Проверка с физического второго устройства остаётся за владельцем.

    tailscale serve --https=443 off

Эта команда отключает только данный приватный прокси; не используйте Funnel для производственных данных. На текущем ПК Serve настроен и HTTPS-проверка цепочки сертификата и браузерный вход пройдены. В системном пользовательском прокси добавлено исключение только для точного собственного домена tailnet; настройки сервера прокси сохранены. В отдельном shell-тесте Windows Schannel не смог получить сведения об отзыве сертификата (CRYPT_E_REVOCATION_OFFLINE); проверку сертификата не отключали. Node TLS и Chrome успешно проверили тот же адрес.

## Питание и перезагрузка

При текущей схеме питания от сети STANDBYIDLE=0 и HIBERNATEIDLE=0: автоматический сон и гибернация отключены. От батареи сон через 900 секунд. Настройки питания не менялись. Ручной сон, выключение ПК и выход из Windows останавливают работу процесса; блокировка экрана сама по себе не означает выход из пользователя.

Для полного приёмочного испытания настоящего входа Windows необходима перезагрузка, только после отдельного подтверждения владельца. До неё выполнены реальные регистрация/запуск задания, автоматическое восстановление после аварии и проверки фоновой работы; это не выдаётся за фактическую перезагрузку. Перед ней сохранён защищённый baseline истории, чтобы затем сверить новый boot time, агент/OAuth после входа и сохранность SQLite.
