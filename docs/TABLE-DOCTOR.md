# Table Doctor — этап 2

## Что реализовано

Table Doctor встроен во вкладку AI Center. Фоновый локальный агент проверяет документы независимо от браузера. Его новые модули:

| Файл                    | Ответственность                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| agent/googleSheets.js   | JWT сервисного аккаунта, scope spreadsheets.readonly, GET метаданных и ограниченных диапазонов, таймауты и ограниченные повторы |
| agent/doctorRegistry.js | Реестр документов, листов, диапазонов, правил и исключений                                                                      |
| agent/doctor.js         | Детерминированная диагностика исходных формул, результатов, заголовков, чисел, дат и UID                                        |
| agent/doctorService.js  | Плановые и ручные проверки, сохранение подтверждённых формул, независимые состояния доступности и данных                        |
| agent/doctorDemo.js     | Явно включаемая локальная фикстура; никогда не обращается к рабочей таблице                                                     |
| agent/store.js          | SQLite v2, инциденты, история переходов, заявки на будущее исправление                                                          |
| src/TableDoctor.tsx     | Документы, фильтры, карточка, ручная проверка, заявки и игнорирование                                                           |

Существующие worker/assembly.js и worker/printing.js на этом этапе не меняются. Коэффициенты FBO и фактические квадратные метры из «Журнал выпуска» не пересчитываются доктором.

## Реальные источники и границы контроля

В реестре два документа: FBO итого и СЕЗОННАЯ ПЕЧАТЬ КРАСНОЕ ЗДАНИЕ.

- FBO: «Все коэффициенты», A1:F10. B/C/D содержат исходные IMPORTRANGE; E — итоговый коэффициент. Это ограниченная область проверки, не вся цепочка связанных документов. Для новых строк и связанных документов расширьте реестр после проверки структуры.
- Печать: 11 зарегистрированных поставок, A1:AF2000 на лист, и «Журнал выпуска», A1:M3000.
- J поставки — плановая площадь, O — количество, AF — UID. Кандидат шаблона J: =F{row}*H{row}*I{row}\*O{row}.
- Журнал: A ID, B производственная дата, H UID заказа, J количество, L площадь. L заполняется скриптом обычным значением: формула здесь **не обязательна**.
- Правила формул FBO и J отмечены pending. Наблюдение формулы не означает, что владелец утвердил её для всех типов строк.
- KPI печати продолжает использовать только уникальные валидные операции «Печать». Диагностика не заменяет площадь журнала расчётом по рулонам.
- Рабочий календарь контроля обновления по умолчанию не настроен. Выходной или отсутствие записи не считается нулевой производительностью.

Без сервисного аккаунта интерфейс показывает «Не настроено», не нулевое число проверенных реальных формул. CSV-мониторинг первого этапа продолжает работать.

## Подключение Google Sheets API

1. Создайте отдельный Google Cloud проект либо используйте разрешённый проект владельца. Включите Google Sheets API.
2. Создайте сервисный аккаунт только для мониторинга. Не предоставляйте ему роли владельца/редактора проекта ради чтения таблиц.
3. В Google Sheets поделитесь только разрешёнными документами с адресом сервисного аккаунта, роль **Читатель**.
4. Создайте ключ сервисного аккаунта JSON. Сохраните, например, в %LOCALAPPDATA%\RITMIntelligence\google-key.json — **вне папки Git**. Каталог после Initialize-Agent ограничен текущим пользователем и SYSTEM. Не добавляйте JSON в репозиторий и не вставляйте его в чат.
5. В защищённом локальном config.json добавьте RITM_GOOGLE_CREDENTIALS_FILE с абсолютным путём к файлу. Либо задайте одноимённую переменную процесса при CLI-запуске.
6. При необходимости задайте RITM_DOCTOR_REGISTRY — абсолютный путь к собственному JSON-реестру. Изменение правил требует перезапуска агента.
7. Перезапустите агент. Во вкладке Table Doctor нажмите «Проверить таблицы». HTTP 403 означает, в частности, необходимость проверить доступ документа и включённый API; недоступность не закрывает прежние инциденты.

Клиент сам подписывает JWT, запрашивает исключительно https://www.googleapis.com/auth/spreadsheets.readonly и использует только GET для Sheets. OAuth POST применяется только для получения токена. Redirect запрещён, секретные пути/ключи/токены не попадают в публичные настройки API.

Официальные источники:

- https://developers.google.com/identity/protocols/oauth2/service-account
- https://developers.google.com/workspace/sheets/api/scopes
- https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get
- https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/cells

## Реестр и утверждение правил

Экспортируйте исходный реестр без секретов в локальный файл:

    node --input-type=module -e "import fs from 'node:fs'; import {DEFAULT_DOCTOR_DOCUMENTS} from './agent/doctorRegistry.js'; fs.writeFileSync(process.argv[1],JSON.stringify(DEFAULT_DOCTOR_DOCUMENTS,null,2));" "C:\путь-вне-Git\doctor.private.json"

Каждый документ содержит id, documentId, name, department, enabled, adapter=google, purpose, sheets и необязательный freshness. Каждый лист содержит точные gid/name, maxRows, lastColumn, headers и rules. Один диапазон ограничен 100000 ячеек.

Пример **только тестового** утверждённого правила:

    {
      "id": "test-coefficient",
      "kind": "formula",
      "column": "G",
      "startRow": 246,
      "endRow": 247,
      "when": {"column": "A", "notEmpty": true},
      "approval": "approved",
      "templates": ["=C{row}/D{row}"],
      "exceptions": [
        {
          "rows": [246],
          "templates": ["=SUM(C246)/D246"],
          "reason": "Альтернативный шаблон для контрольной строки"
        }
      ],
      "result": {"kind": "ratio", "columns": ["C", "D"], "tolerance": 0.000001},
      "impact": "Искажение тестового коэффициента"
    }

Для реальных правил approval=approved ставит владелец после подтверждения диапазона, формулы и исключений. Не копируйте тестовое правило в производственную таблицу.

- templates сравниваются точно после удаления краевых пробелов; пробелы/локализованные разделители внутри формулы не переписываются автоматически.
- {row} подставляет текущую строку.
- when допускает equals или notEmpty по указанному столбцу.
- exceptions задаёт rows и/или when с обязательным reason. Без templates правило для этих строк пропускается; с templates используется альтернативный шаблон.
- Разные типы строк оформляются разными when/правилами и исключениями.
- ARRAYFORMULA, LET и QUERY проверяются по якорной ячейке. Для результатов разлива не объявляйте обязательные формулы.
- allowedDocumentIds задаёт разрешённые статические ссылки IMPORTRANGE. Динамически вычисляемые ссылки этим анализатором не доказываются.
- result поддерживает product, sum, ratio; границы minimum/maximum — для number/integer.
- Проверенный снимок создаётся только для формулы, соответствующей утверждённому шаблону. В карточке он используется только при совпадении версии правила. Соседние ячейки не являются эталоном.

freshness требует sheetId, column, startRow, endRow, maximumAgeMinutes, activeWeekdays (0=воскресенье), startHour и endHour по московскому времени. Его нужно согласовать с рабочим расписанием. Отдельное отсутствие записи не доказывает простой.

## Инциденты и локальные действия

Статусы: «Новая проблема», «Требует проверки», «Подтверждена», «Исправлена», «Игнорируется».

Первая подтверждённая правилом проблема — новая; повтор подтверждает устойчивое нарушение. Pending-шаблоны остаются «Требует проверки». Гипотеза ручного редактирования явно не считается доказанной причиной.

Один fingerprint на источник/лист/ячейку/тип обновляется при повторных проверках. После успешного полного чтения исчезнувшая ошибка закрывается как «Исправлена»: это результат проверки, **не действие агента с таблицей**. При недоступности API или нарушенной структуре прежние ошибки не закрываются.

«Отметить для исправления» сохраняет идемпотентную локальную заявку на будущий этап. «Игнорировать» записывает решение владельца и прекращает уведомления. Никакого Sheet write endpoint нет. SQL мигрирует существующую базу v1 без потери истории.

## Контролируемая демонстрация

В config.json задайте RITM_DOCTOR_DEMO_ENABLED="true" и перезапустите агент. Для обычной эксплуатации оставьте false.

Откройте http://127.0.0.1:4318/?page=intelligence, войдите и выберите Table Doctor.

1. Источник «ДЕМОНСТРАЦИЯ · Сборка QA» — отдельный локальный JSON в каталоге данных.
2. Нажмите «1. Заменить формулу числом в DEMO». Только G247 фикстуры меняется с =C247/D247 на 150.
3. Откройте новую проблему. Карточка показывает число, эталон, причину-гипотезу, тестовое влияние и адрес G247.
4. При необходимости сохраните заявку; она не выполняет исправление.
5. Нажмите «2. Повторить проверку». ID тот же, наблюдений больше, статус «Подтверждена».
6. Нажмите «3. Восстановить DEMO-формулу». Повторное чтение закрывает инцидент.
7. Посмотрите «История»: обнаружение, подтверждение, заявка, восстановление и повторная проверка сохранены.

Ссылки на рабочий Google документ у фикстуры нет. Telegram для демонстрационных проблем отключён. Демо-коэффициенты не попадают в сборку/печать.

## Telegram

Используется существующая защищённая DPAPI-настройка Windows: Initialize-Agent.ps1 с ConfigureTelegram и RITM_TELEGRAM_ENABLED=true в локальном config.json.

Новые нарушения утверждённых правил реального источника поступают в постоянную очередь. Повтор той же открытой ошибки не создаёт новую отправку. Review и DEMO не отправляются. Исчезновение/игнорирование отменяет ожидающие сообщения. Неизвестный результат сетевой отправки блокирует автоматический дубль. Входящих команд, кнопок исправления и доступа на запись нет.

## Публикация GPT Sites

Production Worker и упаковщик Sites не менялись. UI можно публиковать отдельно: build не содержит локальную SQLite, секреты Google или снимки агента. Публичный Worker не предоставляет /api/intelligence и не проксирует localhost. В публичном AI Center отображается «Локальный агент не подключён» со ссылкой на локальный кабинет, без раскрытия его данных.

Автоматический production-деплой не выполнялся. Для будущего общего кабинета нужен постоянно работающий защищённый HTTPS backend с авторизацией владельца/пользователей, отдельным хранилищем и ограниченным сервисным доступом. Публиковать локальный порт напрямую нельзя.
