## Реализация

Машинная порезка: количество изделий × листов на изделие / норму листов за смену. Ручная резка / сборка / прочее: количество / норму D. Упаковка: количество / норму C. Все количества ввода и прогресс поставки по-прежнему в изделиях, пересчёт листов используется только для коэффициента.

`resolveWorkNorm_` — единый серверный выбор нормы для чтения формы и записи WorkLog. Сохраняется совместимый знаменатель в шт./чел. за смену: для порезки это норма листов / листов на изделие. Поэтому сохранённое отношение quantity/norm равно исходной формуле FBO. Персональная норма OperationNorms сохраняет приоритет. При сохранении лист норм читается заново; подсказка может использовать кэш до 60 секунд, ручное обновление принудительно перечитывает нормы.

Каталог передаёт `Кол-во листов` в дополнительную последнюю колонку зеркала `Листов на штуку`, без смещения существующих колонок и идентификаторов. Подтверждённое поведение FBO для пустого числа листов — множитель 1. Отсутствующий заголовок, ошибка, нулевое или отрицательное значение остаются неизвестными.

Сменный итог формы — сохранённые коэффициенты WorkLog источника WEB_APP_RITM за московский день по всем поставкам приложения. Дубликаты eventId/idempotencyKey не увеличивают итог. Форма показывает ориентир упаковки до кэфа 1: floor(норма упаковки × max(0, 1 − сумма вкладов)). Это не ограничение ввода факта и не признак ошибки при перевыполнении.

FBO и его исторические коэффициенты не суммируются с WorkLog, чтобы не создавать второй учёт одной работы. Исторические события не переписываются при изменении нормы. Старые записи без нормы остаются неизвестными; при их наличии остаток смены не показывается как точный. Частичные коэффициенты в карточке помечаются `+ ?`.
