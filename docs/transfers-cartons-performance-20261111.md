# Переносы и короба — 11 ноября 2026

## Массовый перенос

Список до 500 позиций разбивается на неизменяемые пакеты до 10. Пакет сохраняется до внешних записей. Для него один раз читаются и разбираются оба производственных листа и журнал; затем выполняется прежний протокол: блокировка исходных строк, одна вставка назначения, проверка всех новых UID, удаление только исходных полей, подтверждение связи участков.

Пакет использует отдельную квитанцию, включающую каждую строку, UID, артикул и количество. При потере ответа или частичном очищении продолжение использует тот же состав и ID. Конфликт любой позиции останавливает очищение всего пакета. Завершённый пакет восстанавливает все результаты даже при потере последнего сохранения родительского списка. Старые одиночные операции продолжаются без преобразования в пакеты.

Режим включается только после ответа обоих шлюзов с `move-group-v1`, через `RITM_MOVE_GROUPS_ENABLED`. Проверки работы, истории рулонов, принадлежности поставке и совпадения количества сохранены.

## Assembly

Состав открытых и закрытых коробов включён в уже загружаемый ответ списка. Раскрытие использует этот ответ; сворачивание закрытого короба больше не перечитывает страницу. После размещения обновлённый состав приходит с подтверждением записи. Отложенный ответ закрытых коробов не может подменить новое выбранное направление.

Повторные чтения операционных таблиц объединяются только внутри одного запроса чтения: сохраняются узкие колонки ключей и найденные блоки строк, без загрузки всей истории состава коробов. При записи этот кэш запрещён: факт упаковки, распределение и вместимость снова проверяются под ScriptLock. Справочник открывается один раз на запрос, без хранения производственных количеств между запросами.

## Рулоны запасов

Временный Google RPC INTERNAL при чтении повторяется не более двух раз с задержкой. Записи рулонов и фактов автоматически не повторяются. Неудачное обновление не очищает последнюю подтверждённую карточку. Ответы чтения нормализуются до сериализуемых значений; фоновый опрос не конкурирует с проверкой KPI.

Для проверки используется существующее защищённое действие health шлюза. Параметр `stockRollPanelHealth=1` в существующем маршруте статуса доступен владельцу и подписанному локальному мосту; менеджерам и анонимным посетителям запрещён. Ответ содержит только результат чтения, без ключей подключения.

Исправлен переход к ответу Google в Worker: `redirect: manual` вместо неподдерживаемого `error`. Разрешён только первый переход на Googleusercontent; второй редирект отклоняется. Секрет передаётся только исходному шлюзу.
