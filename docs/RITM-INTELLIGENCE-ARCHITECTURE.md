# RITM Intelligence — архитектура первого этапа

## Аудит существующего проекта

RITM использует React 19, TypeScript, Vite и JavaScript Worker. Навигация и страницы находятся в src/App.tsx, общие контролы — в src/ui.tsx. Worker предоставляет /api/assembly и /api/printing. Действующие обработчики и расчёты сохранены; worker/index.js и упаковка Sites не изменены.

Сборка читает историю FBO «Итого». Коэффициенты остаются рассчитанными исходной таблицей. «По дням · Дашборд» — дополнительный источник сверки, а не добавка к истории. Автоматическая сверка пока не настроена: требуется утверждённый период и схема.

Печать использует существующий worker/printing.js, «Журнал выпуска», операцию «Печать», производственную дату B, сотрудника C, количество J и площадь L. Метка M используется только для актуальности источника. Резка и расчёт площади по рулонам не добавляются в KPI.

CSV содержит результаты формул. Проверять исходные формулы по CSV нельзя. В первом этапе авторизованный Google Sheets API не настроен.

## Изоляция агента

Отдельный долгоживущий процесс Node.js 24.12+ выполняет программные проверки и обслуживает защищённый кабинет на http://127.0.0.1:4318. Он работает независимо от браузера.

| Компонент         | Ответственность                                                             |
| ----------------- | --------------------------------------------------------------------------- |
| agent/registry.js | Реестр документов, листов, колонок и правил                                 |
| agent/adapters.js | Проверка источников и контрактов API                                        |
| agent/monitor.js  | Независимые проверки, повторные попытки, актуальность                       |
| agent/store.js    | SQLite, инциденты, снимки, история, очередь уведомлений, аренда процесса    |
| agent/server.js   | Доступ владельца, API только чтения, локальная копия существующего frontend |
| agent/telegram.js | Исходящие уведомления с защитой от повторов                                 |
| agent/index.js    | Цикл проверок, heartbeat, завершение и логи                                 |
| src/AICenter.tsx  | Обзор, инциденты, подробности, рекомендации, история и настройки            |

SQLite находится вне репозитория, по умолчанию в %LOCALAPPDATA%\RITMIntelligence. В Worker базы нет. Модуль хранилища отделён от мониторинга для последующего перехода на PostgreSQL. Встроенный node:sqlite в используемой версии Node выдаёт предупреждение ExperimentalWarning.

Два штатных адаптера сохраняют утверждённые источники. Для новых отделов можно добавить CSV-источник с явными колонками и проверками number, integer, date, required, unique. Подключение других структур и сверок требует отдельного адаптера.

## Проверки и честность показателей

Некорректные числа, даты, обязательные ключи, дубли и повреждённые строки сборки исключаются с диагностикой. Пустое или ошибочное число не превращается в ноль. Валидные коэффициенты и формулы агрегации не изменены.

Проверяются источники, доступность API, схема ответа, длительность запроса, возраст снимка и доступность HTML приложения. Длительность включает сеть и повторные попытки; это не измерение только вычислений сервера. Проверка HTML не доказывает работоспособность всех frontend-экранов: отдельная браузерная проверка нужна после изменений.

Предыдущий проверенный снимок сохраняется при ошибке или частичных данных. Локальное API явно помечает его stale. Если проверенного снимка нет, API возвращает 503 вместо нулевых KPI. Интерфейс различает отсутствие записей, ошибки источника и устаревшие данные.

Отсутствие данных за выходной не является ошибкой. Проверка прекращения выпуска отключена до настройки утверждённых активных дней, часов и допустимого возраста данных в freshness реестра. Возраст API-снимка и возраст производственной записи — разные проверки.

## Инциденты и уведомления

Инцидент содержит источник, лист, строку/ячейку, тип, обнаруженное и ожидаемое, влияние, действие, время и ссылку. Причина не объявляется доказанной без данных.

Fingerprint объединяет scope, источник, лист, ячейку и тип. Повторная проверка обновляет тот же инцидент. Успешная проверка закрывает исчезнувшую проблему; ошибка чтения её не закрывает. Закрытие инцидента не считается выполненным исправлением.

Критические и высокие инциденты попадают в постоянную очередь Telegram. Повторные проверки не создают новых уведомлений. Повторно открытый инцидент имеет новую генерацию. Для 429/5xx используются ограниченные повторные попытки. При неизвестном результате отправки или аварии во время отправки статус uncertain: повтор автоматически не отправляется, чтобы не дублировать сообщение. Гарантировать одновременно отсутствие дублей и доставку при неизвестном результате Bot API нельзя.

Уведомление содержит кнопку исходной ячейки. Публичные ссылки на приватные подробности локального кабинета и команды подтверждения не реализованы.

## Защищённый API

Все данные /api/intelligence и локальные снимки /api/assembly, /api/printing доступны только владельцу. Ключ минимум 32 символа. Авторизация выдаёт временную HttpOnly SameSite=Strict cookie, ключ не сохраняется в localStorage. Есть проверка Host, Origin и cross-site metadata, ограничение попыток входа и срок сессии.

| Метод и путь                        | Назначение                    |
| ----------------------------------- | ----------------------------- |
| POST /api/intelligence/session      | Вход владельца                |
| DELETE /api/intelligence/session    | Выход                         |
| GET /api/intelligence/status        | Проверки, состояние, счётчики |
| GET /api/intelligence/settings      | Несекретные настройки         |
| GET /api/intelligence/incidents     | Серверные фильтры и пагинация |
| GET /api/intelligence/incidents/:id | Подробности                   |
| GET /api/intelligence/history       | Хронология                    |
| GET /api/assembly и /api/printing   | Проверенные снимки            |

Остальные операции записи запрещены. Ни агент, ни языковая модель не имеют инструмента изменения таблиц. Сервер слушает только loopback. Не открывайте порт наружу и не добавляйте публичный proxy приватных API без полноценной авторизации.

В публичном RITM пункт AI Center показывает отсутствие локального подключения. Полноценный кабинет первого этапа открывается через локальный адрес с тем же frontend. Продакшен Worker не получает приватные endpoints.

## AI и рекомендации

LLM не вызывается: расходы AI API равны нулю. AI-чат, формульный Doctor и исправления честно отмечены «Не настроено» либо недоступны. Настройка модели зарезервирована для следующего этапа; конкретная модель не зафиксирована.

Программные рекомендации основаны на измеренных задержках и повторяющихся сбоях. Они содержат доказательство, предлагаемое решение, пользу, риски, приоритет и способ проверки. Предполагаемая польза не выдаётся за измеренное ускорение.
