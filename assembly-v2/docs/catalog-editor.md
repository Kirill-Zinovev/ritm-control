# Управление справочником

Владелец открывает «Справочник». «Добавить товар» создаёт новую карточку; нажатие на артикул → «Редактировать товар» открывает редактор.

- «Товар»: название, штрихкод, категория и связанные артикулы. Артикул, маркетплейс и магазин служат идентификаторами: для другой комбинации создаётся отдельная карточка, а существующие остатки не переводятся между магазинами.
- «Производство»: вид, станок, участок печати, упаковка, размер, листы, папка печати, кратность, тип и вместимость короба. Необязательные нормы операций задаются в готовых изделиях за смену; пустая норма наследуется из вида товара. Изменение применяется только к новой работе.
- «Фото и этикетка»: загрузка PNG/JPG/WebP до 8 МБ. После сохранения этикетка доступна для печати и скачивания как в поставке, так и для товара на склад. Для фото также поддерживаются существующие разрешённые ссылки WB.
- «История»: последние 20 изменений с предыдущими и новыми значениями. Полная история хранится в базе.

Сохранение — атомарная команда с ключом повторного запроса и проверкой версии карточки. Новые данные доступны следующим запросом; открытый экран сборщика получает их при штатном обновлении ревизии (до 5 секунд при наличии связи). Новый товар появляется в справочнике и выборе товара на склад; для работы по поставке его необходимо включить в поставку через РИТМ.

`av2_catalog_products` хранит правки отдельно от исходных Excel. Повторный Excel-импорт не стирает эти правки. `av2_quality_repairs` содержит неизменяемые записи до/после. Файлы хранятся в R2 по SHA-256, метаданные — в `av2_catalog_media`; загрузка сама по себе не публикует привязку к товару, она применяется при сохранении карточки.

В текущих позициях обновляются данные карточки. Вместимость пересчитывается для вложений в короба без отгрузки/резерва. Количества вложений, записи работы, сохранённые нормы и коэффициенты, отправленные события РИТМ и зафиксированные экспорты не переписываются. Справочник старого Assembly и исходные Google Sheets не изменяются.

Миграция 0024 добавляет две таблицы и меняет только представления чтения; существующие строки не обновляет. При откате к предыдущей версии кода таблицы и историю правок сохранять. Не откатывать производственную базу целиком поверх новой работы сотрудников.
