# Передача нового Assembly сборщикам

Решение владельца от 14.11.2026: без регистрации и личных PIN. Сборщик открывает рабочую ссылку и выбирает своё имя при записи. Последнее имя помнится в текущем сеансе; следующая форма сразу фокусирует количество. Внешний вид и левый список поставок сохранены.

## Доступ

Владелец открывает «Управление → Подключение → Ссылка для сборщиков». Ссылка содержит секрет в URL fragment. Приложение обменивает его на подписанный HttpOnly/Secure/SameSite cookie, затем убирает fragment из адресной строки. Срок сеанса — 180 дней. Регистрации и PIN нет. Передавать ссылку только сотрудникам.

Без рабочей ссылки API не отдаёт производственные данные. Рабочая ссылка разрешает сборку, просмотр выработки и складские поступления. Имя является атрибуцией работы, не удостоверением личности: сотрудники могут выбрать любое активное имя, как в старом Assembly. Импорт, резервные копии, изменение справочников, выгрузки отгрузок и отправка требуют прав владельца. Владелец определяется отдельным Sites user ID. Служебный API владельца имеет отдельный секрет; РИТМ получает только подписанные узкие маршруты.

Для отзыва ссылки меняются runtime AV2_COLLECTOR_ACCESS_TOKEN и соответствующий SHA-256 AV2_COLLECTOR_ACCESS_HASH. Старые ссылки и cookies перестают работать. Не менять эти значения при обычной публикации. AV2_SESSION_SECRET и AV2_OWNER_API_TOKEN также не входят в исходники.

AV2_OWNER_USER_ID — подтверждённый `oai-authenticated-user-id` владельца именно в этом Site. Это не UUID аккаунта из workspace allowlist; ID в другом Site также отличается. Проверять вход владельца через браузер до передачи рабочей ссылки.

## Рабочий порядок

1. Проверить активных сотрудников и поставить рабочую ссылку на устройства.
2. Один физический результат записывать в одной версии Assembly. Старую версию оставить доступной для истории и перехода. Перед началом другой смены в старой версии нужна повторная сверка событий и номеров: постоянного зеркалирования старых записей в новую базу нет.
3. Работа: поставка → артикул → имя/операция/количество → сохранить. У упаковки есть «После записи перейти к коробам». Ошибка оставляет форму и тот же ключ повтора.
4. Короба: выбрать открытый либо новый черновик → количество → добавить. Новый номер и первое вложение сохраняются вместе. Закрытие требует проверки состава и не отмечает выезд.
5. В РИТМ открыть «Склад». Выбрать закрытые короба флажками. «Excel для учёта» сохраняет состав и скачивает файл. «Для маркетплейса» заполняет загруженный пустой шаблон после сопоставления колонок и предпросмотра. Номер Assembly не заменяет штрихкод грузоместа из кабинета.
6. «Отметить выезд» требует отдельного подтверждения фактической отправки. Сервер повторно проверяет закрытие и состав. Повтор не создаёт новую отправку. Возврат не меняет снимок предыдущего выезда.

## Сохранность и связь

Факты находятся в D1. Браузер хранит только предпочтения; закрытие вкладки не удаляет работу. Работа и событие РИТМ фиксируются одной транзакцией. Доставка повторяется с постоянными ID, также при обращениях РИТМ без создания поставки. Сбой сети задерживает доставку, но не удаляет подтверждённую запись. Неподтверждённую запись интерфейс не объявляет сохранённой и не ставит скрыто в очередь браузера.

Перенесённые короба объединяются по исходным ID. Старый и новый состав сверяются с базовой версией. Изменение одного короба в обеих версиях либо одинаковый номер у разных коробов блокирует отправку до сверки. Новые собственные короба можно отправлять при недоступном старом источнике; устаревшая часть помечается отдельно. Поставки идут в обе версии через независимые очереди. Старые URL, ключи, Apps Script, Sheets и квитанции не изменены.

Контрольная выгрузка старой книги от 14.11.2026 12:16 МСК совпала с переносом по WorkLog, WorkLogCorrections, Cartons, CartonContents, Employees, «нормы» и идентичности позиций. Исходные XLSX, JSON и подтверждения резервных копий остаются в закрытом R2 и `.local/`. Публикация не заменяет D1 тестовым хранилищем.

## Нормы и ограничения источника

Журнал показывает сохранённые норму и коэффициент. Отмены исключены из итогов, известная часть коэффициента считается отдельно от неизвестной. Известные исторические нормы не пересчитываются при исправлении справочника. По поручению владельца от 14.11.2026 прежде отсутствовавшие нормы восстанавливаются с аудитом и отдельным событием РИТМ; демонстрация и пробные записи исключаются из рабочего учёта с сохранением истории. См. `data-quality-repair.md`.

Для OZON / магазин 1 / KT0008.A6764(OZ) владелец подтвердил «Наклейки А5 3-4 листа»: упаковка 825, ручная резка 550. Поправка используется при пустом исходном виде, исходные импортированные строки сохраняются. Другие площадки и магазины не меняются.

В источнике есть незаполненные нормы отдельных операций и неподтверждённые исторические вместимости. Они остаются неизвестными: количество записывается, отсутствующая норма не превращается в выдуманный коэффициент. Частный отчёт: `.local/handoff-20261114/norm-audit.json`. Один старый отправленный короб без оригинального снимка не получает выдуманную историческую выгрузку.

## Откат

После открытия рабочей ссылки нельзя откатывать Assembly к версии 16 и старше: они рассчитаны на owner-private платформенный доступ и не содержат разграничения. Сначала вернуть Sites в owner-only либо публиковать только версию с текущим слоем доступа. Откат интерфейса не переносит новые факты в Google Sheets. Не очищать D1, не сбрасывать ключи команд и не запускать импорт как замену базы.
