# Исправления данных 14.11.2026

Владелец поручил исправить восемь позиций без магазина и 105 записей без нормы только в новом Assembly. Разбор: 91 запись явной TEST-поставки; две подтверждённые пробные упаковки по 50 шт.; одна неподтверждённая порезка 500 шт. с сотрудником Максимом; 11 рабочих записей с восстанавливаемой нормой. Известные коэффициенты и исходные количества защищены.

`quality.resolveStores` требует совпадения хеша карточки WB, явных OZON-артикула, OZON-штрихкода и магазина и однозначности всех исходных строк. Ссылка хранится отдельно от неизменного импорта. Собственная карточка OZON имеет приоритет; общего WB fallback нет. Позиция переводится в подтверждённую группу только без работы, вложений и складского остатка. Её ID и внешний ID сохраняются, замок не снимается. Пустая прежняя группа сохраняется в базе.

`quality.repairNorms` заполняет отсутствующий коэффициент по сохранённой норме либо подтверждённым карточке своей площадки и нормам за смену. Историческая позиция без карточки требует совпадения норм всех подходящих карточек своей площадки. Станочная резка учитывает листы в изделии. Упаковка и ручная резка используют изделия. Отсутствие или конфликт нормы блокирует весь пакет.

Значения до/после и основания сохраняются в неизменяемом `av2_quality_repairs`. Исходный legacy JSON не меняется. В РИТМ передаётся отдельное подписанное событие `norm`, привязанное к исходному ID работы, позиции, количеству, операции, сотруднику и времени. Оно не добавляет работу. Известный коэффициент не меняется; несовпавшее исправление попадает в диагностику. Исходный пакет работы и его хеш остаются прежними.

`quality.archiveDemo` принимает только явную TEST-поставку без канонического RITM ID и с DEMO-позициями. Факты, вложения и номера сохраняются отдельно от рабочего контура. Владелец может читать полный журнал через `includeDemo=1`.

`quality.excludeWork` сохраняет оригинал и отдельную отмену с основанием. Причина для Максима означает неподтверждённое происхождение, а не доказанное отсутствие физической работы. Пробная упаковка исключается автоматически только если вся упаковка позиции относится к этой записи и нет закрытых/зарезервированных коробов или складских размещений. Вложения снимаются и итоги меняются атомарно. Пустой пробный короб скрывается, его номер остаётся занят. Короба с другими товарами остаются видимыми. Снимки отправки и Excel не меняются.

Команды доступны владельцу, ограничены по размеру и защищены ревизией и постоянным ключом повтора. Перед применением сохраняются проверенные обратным чтением копии в закрытом R2. Восстановление использует значения аудита и отдельные согласованные компенсирующие операции; старую копию нельзя накладывать поверх новых рабочих записей.

Старый Assembly, Google Sheets, Apps Script и старая очередь поставок РИТМ не изменяются. Исправления и отмены используют отдельный канал новой версии.
