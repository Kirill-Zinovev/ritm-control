# Assembly v2

Отдельная первая версия для проверки владельцем. Рабочий Assembly, старый RITM, Google Sheets, существующие Supabase-проекты и их развёртывания не изменяются.

Адрес новой площадки: https://assembly-v2.zinovevkirill234.chatgpt.site (публикацию подтверждает отдельный результат развёртывания).

## Что реализовано

- Сборщик: сохранён прежний компактный дизайн Assembly, поставки слева, три раздельных этапа, раскрываемая история. «Записать работу» открывает привычное окно: сотрудник, операция, количество. Имя сохраняется в текущем сеансе. Перевыполнение допустимо.
- «Добавить в короб» открывает правую панель с упакованным остатком, выбором короба и закреплённым блоком количества. Совместимость по маркетплейсу, магазину и точному назначению. Вместимость микса по долям норм. API также поддерживает атомарную упаковку сразу в короб; в привычном интерфейсе оставлены отдельные действия, как в старой версии.
- Проверка состава, закрытие короба, склад закрытых неотправленных коробов, выбор на отгрузку, резервирование, отмена подготовки и отдельное подтверждение фактического выезда.
- Excel для учёта: «Короба», «Состав», «Сводка». Исходные ID и штрихкоды — текст. Повторные вложения одной позиции в один короб объединяются в строку состава. Снимок выгрузки неизменяем; состав фиксируется также при фактическом отправлении.
- Заполнение загруженного пустого .xlsx по выбранным колонкам. Проверка перед скачиванием; занятые клетки не перезаписываются. Это механизм заполнения шаблона, совместимость с реальным кабинетом WB/Ozon ещё нужно проверить на ваших файлах.
- Импорт поставки JSON с исходными RITM ID и номером версии. Повторы не создают дубли. Старый маршрут RITM не переключён. Новая отдельная связь описана в docs/RITM-CONNECTION.md.

## Устройство и скорость

React 19 + TypeScript + Vite; сервер Cloudflare Worker; отдельная Cloudflare D1. Supabase сообщил стоимость $0, но отказал в создании нового проекта из-за лимита двух активных бесплатных проектов аккаунта. Ни один действующий проект не остановлен и не изменён.

Рабочие записи находятся на сервере, не в браузере и не в Google Sheets. История событий дополняется; исправления не удаляют исходную запись. Итоги позиции и сотрудника обновляются внутри той же транзакции, поэтому история не сканируется при каждом сохранении. Состояние экрана читается одной транзакцией D1, а подтверждение сохранения отделено от последующего обновления экрана. У каждой команды есть ключ повторного запроса; транзакционный D1 batch и проверки актуального остатка, готовности, магазина и вместимости в базе защищают от одновременного списания. Независимые записи работы не повторяются из-за общей ревизии; ревизия сохраняет защиту управляющих действий. Ревизия проверяется раз в 30 секунд только в видимой вкладке, полные данные запрашиваются при изменении. Excel загружается отдельным модулем только при открытии выгрузки.

При ошибке связи форма сохраняет введённое количество; повтор того же запроса использует тот же ключ. Не показываем успех до подтверждения сервера. Незаписанное количество защищено при переходах.

## Локальная проверка

Требуется Node.js 24 (используется встроенный node:sqlite).

```powershell
npm ci
npm run dev
```

Открыть http://127.0.0.1:5178. Локальная база `.local/assembly-preview.sqlite` принадлежит только новой версии. Для явно подписанного тестового примера:

```powershell
node --import tsx scripts/seed-review.ts
```

Скрипт ничего не меняет, если новая локальная база уже содержит поставки. Встроенные данные имеют названия «ТЕСТ» и «Тест: …». Облачная и локальная базы независимы.

Проверки: `npm run typecheck`, `npm test`, `npm run build`, `npm run verify:legacy`. Схема: `db/schema.cjs`; генерация: `npm run db:generate`. Применённые миграции `drizzle/` не редактировать, добавлять новые. Начальный набор миграций предназначен для новой пустой базы, не для старого Assembly. Данные или пересчёт исторических итогов нельзя добавлять в миграции.

## Что отделено от рабочего запуска

1. Автоматическая передача поставок из старого RITM не включена: сейчас доступен проверяемый импорт JSON в новую базу. Переключение маршрута потребует отдельного согласования.
2. Сайт закрыт для владельца. Разделы сборщика и склада сейчас являются режимами проверки владельцем, а не разграничением ролей. До выдачи доступа сотрудникам нужно настроить и проверить роли.
3. Рабочие остатки, старые короба, журнал и нормы выработки/KPI не переносились. Текущая версия считает количество по операциям, без расчёта коэффициентов и оплаты. Ручной приход готовой продукции «На склад» из старой версии пока не перенесён.
4. Отмена упаковки, которая уже находится в коробах, требует предварительно извлечь соответствующее вложение из открытого короба. Автоматическое компенсирующее извлечение старой версии не перенесено; закрытые и отправленные короба защищены от изменения.
5. Фактическая скорость на сети предприятия и полноценная смена 12 сборщиков по 8 часов ещё не проверялись. Локальная конкурентная проверка не является измерением облачной скорости или гарантией бесплатного лимита.
6. Для первой проверки выдача ограничена 300 поставками, 500 позициями выбранной поставки, 500 неотправленными коробами, 100 записями работы и 100 отгрузками/выгрузками. История остаётся в базе. Перед рабочим запуском больших объёмов требуется серверная фильтрация и постраничная выдача архива. Сборщик использует «Показать ещё» по 60 позиций, остальные списки разбиты на страницы.
7. Фото, виды товара/короба, этикетки и контрольные задания старого Assembly ещё не передаются в новую схему. Отсутствующие сведения явно обозначены; фильтр вида пока отключён. Никакие рабочие данные не заменяются выдуманными значениями. Основные поля, журнал и размещение работают с настоящей отдельной базой, а не с макетом в браузере.

Публикация выполняется только для проекта из новой `.openai/hosting.json`. Нельзя подменять этот ID идентификатором старого RITM или Assembly. Контрольные хеши четырёх старых файлов — `legacy-baseline.json`; скрипт только читает их.
