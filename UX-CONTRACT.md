## Feedback and recovery

Department transfers use `DepartmentMove` with the shared Modal, Field and Button. `departmentMoveRequest.ts` keeps the immutable operation ID, waits automatically for a temporary production lease conflict, and reads durable status after a missing response before continuing. The server waits up to five seconds before entering a write scope; it never retries an entered callback. A completed browser request cannot block a different position. Automatic reconciliation is bounded and uses the existing receipt/readback protocol: an unconfirmed destination copy is never replayed, and its source is retained. Actual work or identity conflicts remain blocking. No new confirmation is required for transient waiting within the already approved transfer.

Bulk department transfers use the same safety protocol for each position. A durable parent list saves immutable child IDs before any external write; each request advances one child while holding the production lease. Select positions by article search, select all matching eligible rows across pagination, set the destination machine and a common or per-row print extension. Started work and duplicate destinations rejected before writing are reported per row; uncertain writes stop the queue until reconciliation. Pausing waits for the current position to finish checking. Only the final list result refreshes supply data. Preflight metadata/grid reads are shared only within one request and permanently disabled at the first mutation, including an Apps Script lock. Post-write reads remain fresh. Managers use their existing RITM session for the batch endpoint.

Before advancing a selected position, bulk transfer reconciles an older blocking move only when its original immutable request and relationship to the same shipment or physical sheets are confirmed. Reconciliation uses its existing ID and receipt protocol. One request reconciles at most one older operation; later selected articles remain pending. The UI names that blocking article separately, so it does not suggest the first newly selected article is already moving. An unproven unrelated move is never resumed automatically. Compact move diagnostics are available through the existing authenticated supply-operations GET route without exporting saved cell backups.

Each department move invalidates the printing snapshot at preparation and at commit under the same durable checkpoint. A matching revision is required before an old cached composition can be considered current. A scan cannot publish a half-finished transfer or overwrite a newer move with an older scan. The client refreshes once after the list and awaits a queued forced read when a periodic read is already running; no competing background scan starts from the move endpoint. Same-invocation source lock/removal acknowledgements may be reused after their gateway readback, but lost responses/resumed requests reread durable receipts. Every external write still renews its lease; clean checkpoints do not rewrite journals or repeatedly prune previews.

Assembly warehouse excess uses one current carton per confirmed marketplace and store, across articles and production directions. Existing contents stay in their original cartons. When no current pointer exists, the first open warehouse carton is reused. The employee creates the next carton explicitly with «Новый короб»; only future allocations use it. Carton creation and stock planning share ScriptLock, and creation retries keep the same immutable ID. Warehouse containers are not automatically split by product packing capacity; normal shipment cartons retain their capacity limits. Allocation rows preserve the exact source position, author and date, and empty current cartons remain visible in «На склад».

Explicit Assembly transfer uses the shared Modal, Button and Field components, native department/sheet selectors and a compact checkbox table. Source quantities are read-only; missing or invalid quantities are unavailable, never substituted with zero. Unlinked source sheets allow selecting positions; a linked RITM supply requires its complete confirmed composition. A separate review precedes «Передать только в сборку». Closing retains selection; keyboard dismissal restores focus to the launching button. Pending operations persist in the server outbox; the browser stores only an operation ID for status recovery. A source change blocks transfer and requires refreshing the preview. Repeat transfer preserves existing work and does not duplicate positions. The production sheets are read-only in this flow.

CSV validation is all-or-nothing: duplicate roll/operation IDs, invalid dates, missing fields and invalid quantities block replacement. Retry keeps file and mappings. Reimport replaces a source snapshot; it never adds the same rows twice. Summary FBO coefficients are not imported as additional work operations. Frozen per-operation norms are needed in the export. Imported monthly mean stays unknown without shift records.

## States

Missing/empty/no-results are different from numeric zero. A zero is confirmed by work records or known closed shifts. Current day's goal status is progress. Future days don't contribute. Reserve is limited to free stock, repeats are idempotent, and reserved stock does not increase packing progress. Source shipments and real operations require an explicit relation before joining; the prototype does not invent this join.
